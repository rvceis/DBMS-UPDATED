## ⚙️ How It Works

```
Text File
   ↓
Format Detection
   ├─ Detects: structured_text (indented/hierarchical)
   ↓
Hierarchical Parser
   ├─ Reads indented blocks
   ├─ Creates nested objects: object: {nested: value}
   ├─ Creates arrays: - item
   ↓
Type Inference
   ├─ true/false → Boolean
   ├─ 123 → Integer
   ├─ 45.6 → Float
   ├─ null → Null
   ├─ text → String
   ↓
JSON Document
   {
     "key": "value",
     "nested": {
       "inner_key": value
     },
     "array": [
       {"item": 1},
       {"item": 2}
     ]
   }
   ↓
Store in JSONB Column
   DataRow.data = json_object
   ↓
Schema Auto-Detection
   ├─ Extract field names from JSON keys
   ├─ Infer types (string, integer, array, object)
   ├─ Create SchemaModel + SchemaFields
   ↓
Available for Queries & Reports
```

## 🔗 Relationship Examples Stored in JSON

### Employee-Certification Relationship (1:N)
```json
{
  "employee_id": "EMP-001",
  "certifications": [
    {"cert_id": "EPA-604", "cert_name": "EPA 608"},
    {"cert_id": "NATE-HT", "cert_name": "NATE Heating"}
  ]
}
```

### Building-Room-Employee Relationships (1:N:1)
```json
{
  "building_id": "BLDG-001",
  "rooms": [
    {
      "room_id": "ROOM-101",
      "assigned_employee_id": "EMP-001"
    }
  ]
}
```

### Project-Phase Dependencies (1:N, Hierarchical)
```json
{
  "project_id": "PROJ-2025-001",
  "project_phases": [
    {
      "phase_id": "PHASE-001",
      "dependencies": []
    },
    {
      "phase_id": "PHASE-002",
      "dependencies": ["PHASE-001"]
    }
  ]
}
```

All relationships stored **within the same JSON document** - this is **true dynamic schema with relational support**.
